# V8 网盘播放与片库体验

版本 `2.19.7-jjbitv.8`。用户反馈的具体问题是结果卡片只有小链接可点击、转存和试播按钮造成困惑、播放器缺乏方便的快进，以及大文件播放不流畅。本版沿用 JjBiTV 黑金主题和私人情侣图标，改造这条实际使用流程。

## 搜索与一键播放

搜索结果使用整卡语义链接，鼠标点击、键盘 Enter 和新标签打开均可进入放映室。自动裁剪混入标题的简介，质量标记只反映来源提供的标签；未知质量不会补造“高清”。流式结果以 60 ms 小批次更新，卡片使用 memo、屏外渲染优化和稳定地址，减少大量结果同时到达时的重排。现有七个检索适配器和普通影片并发搜索保持兼容。

分集选中后只显示“播放”。分享资源自动转存这一集、复用已有转存映射，再取得完整播放线路；个人云盘文件直接使用已有文件。按钮下方说明实际转存与清理行为。连续点击受前端忙碌状态与服务端账号级队列约束；状态不明的转存任务先对账，不盲目重复提交。

## 容量不足时的清理

部署环境 `PAN_AUTO_CLEANUP=1` 只是总开关，账号还必须在持久化的 `netdisk-cleanup-policy.json` 中获准。本站用户明确授权当前两个专用账号用于追剧，因此本次发布为这两个连接启用。新连接和重新扫码产生的新连接标识默认关闭，可在连接管理中自行启用。

准备新转存时先查询文件大小和实际容量。空间充足不删除；文件大于网盘总容量直接报错；容量或文件大小无法确认时停止清理。需要释放空间时按回收站、本站旧资源、其他旧资源的优先级处理，同优先级优先较旧条目，容量足够立即停止。此操作包含永久删除，使用范围是获准的整个追剧专用账号，并非仅本站目录。

当前要转存的文件及其上级目录、本站正在播放的文件及其上级目录会被保护。播放租约保存在 `netdisk-leases.json`，30 秒心跳、180 秒过期；当前设备切片释放自己的旧租约，不释放其他设备的租约。保护不覆盖官方网盘 App 或 TVBox 的独立播放。容量更新延迟时只短暂复查，仍不更新就停止，不持续盲目删除。一次最多处理 200 个候选。

阿里使用永久删除接口并处理空响应/异步任务；夸克先移入回收站，再仅清除匹配记录，不整体清空无关的回收站快照。已确认删除的旧转存映射同步移除。写操作要求站点登录及同源验证。

## 播放器和大文件

使用已有依赖 [ArtPlayer](https://artplayer.org/document/en/) 与 [HLS.js](https://github.com/video-dev/hls.js)，不重复增加另一个播放框架。提供进度拖动、显式前后 10 秒按钮、左右方向键/J/L、Shift 加方向键跳转 60 秒、空格/K 暂停、倍速、全屏、画中画、触摸手势，以及已有影院宽屏和定时暂停。手机控制条收紧，保留快进、后退、设置和原生全屏。

播放进度按稳定文件身份保存在本机；换画质和刷新地址保留位置。自动连播偏好也保存在本机。完整转码优先，持续卡顿时“自动流畅”可选择更低的完整线路；限时试看不会混入普通播放候选。文件名或原文件分辨率不代表网页最终播放画质，界面分别显示原文件和实际解码分辨率。

HLS 使用 Worker、60 秒目标前缓冲、20 秒后缓冲、48 MiB 缓冲大小限制。首次播放前预加载播放器代码；存在完整转码时不额外请求原文件下载地址。媒体票据索引和过期清理减少分片请求的服务端遍历。

启用 `PAN_DIRECT_MEDIA=1` 后，仅在该 CDN 无账号 Cookie、无 Referer 的实际 Range 请求通过且支持当前 Origin 时，媒体分片才使用临时签名地址直达 CDN。清单仍由本站鉴权返回，签名地址私有且不缓存；不把网盘登录凭证交给浏览器。CORS/网络失败时播放器仅回退一次到原有服务器代理。未通过探测的线路继续代理。

大文件本身不会在浏览器或本站服务器中一次性载入。本版实测约 81.46 GiB 的 3840×2160 文件，账号接口提供的完整线路为 720P/540P；默认播放实测 1280×720。不能据此声称账号获得完整 4K 权限，也不能承诺任意网络、设备、片源都零卡顿。

## 验证记录

- Linux Debian Bookworm、Node 22：49 个测试文件、565 项测试通过，TypeScript、ESLint、生产构建通过。
- 新增 21 项测试覆盖容量决策、永久清理停止条件、活跃文件保护、账号授权绑定、CDN 探测/回退及画质/跳转工具逻辑。
- 独立浏览器脚本验证整卡点击、一键播放、显式单集转存参数、无额外确认弹窗、清理结果反馈、快进/后退、键盘/鼠标拖动、空格和换画质后保留位置。
- 真实 81.46 GiB 文件完成播放、10 秒快进、60 秒跳转、拖到影片约 95% 继续播放。预发布常规起播样本约 8.5 秒，包含本地到服务器 SSH 隧道和冷启动；15 秒正常播放采样没有 waiting 事件，约 54 秒前缓冲。此采样并非全片、全网络无卡顿证明。
- 人为令一次分片请求失败，验证回退服务器代理后继续播放。正常播放观察到真实网盘 CDN 返回成功分片。
- 正式域名复测：两个账号均连接且当前授权生效；搜索“血战钢锯岭”首个结果样本约 3.6 秒，阿里筛选得到 31 个分享。真实大文件点击播放到画面前进的样本约 8.2 秒，15 秒采样 waiting=0，拖到约 95% 后继续播放。数值为单次观测，不是长期 SLA。
- 夸克正式站复测复用已有转存，清理数为 0；完整视频约 2554 秒，按钮快进与 60 秒快捷键通过。该样本实际仍为 480×270，平台当前网页接口的画质限制没有因更换播放器而解除。
- 两网盘仅创建并删除本次新建的空测试目录，确认删除/回收站接口契约；未为验证清理而删除用户原有影片。容量不足触发后的大规模真实删除由算法测试覆盖，未在用户文件上做破坏性演练。
- 桌面 1505×1045、手机 390×844 检查无页面横向溢出。发现并修复播放器图标被默认填充、手机全屏按钮被挤出的样式问题。

## 设计复核

先生成独立搜索页概念图，再实现真实交互。由于当前任务未提供可用的 Browser 插件专用执行入口，使用本机 Playwright Chromium 截图与真实交互测试；概念和最终截图通过 `view_image` 同轮复核。概念、最终页面截图及测试脚本保存在部署操作目录，不上传包含私人头像的截图到公共仓库。

| 对照点 | 概念依据与最终处理 |
| --- | --- |
| 布局 | 顶部标题/连接状态、长搜索框、筛选行、三列结果顺序一致，1440 px 内容容器；手机降为单列 |
| 文字 | 保留“今晚，找一部好电影。”与私人片库说明；例示来源和影片名改为接口真实内容，结果数由响应产生 |
| 字体 | 无衬线标题、明确标题/来源/状态层级；真实长片名采用较紧凑的 18 px 卡片字与两行截断，手机 16 px |
| 色彩 | 暖黑背景、浅金主按钮、细金悬停边框；没有新增宣传插画或大面积发光背景 |
| 图标 | 搜索、清除、目录、链接、来源人物和圆形箭头使用统一线条；保留现有情侣头像与网站导航，而非概念虚构的通知/账号入口 |
| 密度 | 卡片缩至 170 px，去掉原卡片大片空白和厚分隔；保持完整可点击区域 |
| 响应式 | 390 px 布局无横溢，连接状态并排、操作自然换行，播放器与目录上下分开 |

首屏文字差异为有意调整：继续使用现网导航、真实搜索建议与数据来源；连接管理增加用户要求的空间清理说明。没有虚构海报、质量或资源数量。页面按概念的结构与视觉语言完成复核，而非把概念截图作为静态页面交付。

## 发布与回滚

备份、预发布目录、生产端口及回滚命令见 [operations.md](operations.md)。回滚应用不会恢复云端已经永久清理的资源。数据目录、账号加密凭证、清理授权和播放租约需要与 `.env` 的加密密钥一起备份；这些文件不得进入公开仓库。
